# data/

Shape-only tables and region profiles (addresses, sizes, expected hashes). Never game bytes. Enforced by the no-game-data check described in Docs/architecture.md §14.

## Region profiles: `regions/<serial>.toml`

One per supported disc, loaded by `dq8::core::load_region_profiles()` and validated with `file:line` errors. `schema_version = 1`:

| Table | Keys |
|---|---|
| `[profile]` | `id` (the name of the directory under `baserom/`; letters, digits, `_`, `-`), `serial`, `title`, `region`, `video_mode` |
| `[image]` | `size` in bytes, `sector_size` (must be 2048) |
| `[boot]` | `path` (disc path, `/`-separated, no `;1`), `size`, `sha1` (40 hex, required), `crc32` (8 hex, required), `entry`, `load_address`, `main_memsz`, optional `ctor_table` (`[start, end)` of the static-constructor pointer table crt0 walks; 4-byte aligned, inside the main program; its entries become function starts in the function-map export) |
| `[overlay_window]` | `base`, `end`, `container` (the header magic as a name, e.g. `MWo3`), `header_size` (64 for `MWo3`), `code_offset` (where the text begins relative to `base`; must equal `header_size`), and the loader facts from spike S3, each a 4-byte-aligned address inside the main program: `window_pointer` (the data word holding `base`, the loader's destination), `loader`, `loader_hook` (the empty call after the read), `load_by_index`, `name_table`, `lsn_cache`, `ctor_walker`, `flush_cache_stub`, `mode_variable`; `name_table_order`: the overlay names in `name_table` order, one per `[[overlays]]` row, no repeats |
| `[[overlays]]` | `name` (unique), `id` (the header's `overlay_id`: unique, 1 to 64), `index` (the loader's index: the position of `name` in `name_table_order`, unique), `segment_index` (the matching zero-filesize `PT_LOAD` of the boot ELF, counting load segments from 0 = the main image; unique, ≥ 1), `path`, `text_size`, `data_size`, `bss_size`, `table_entries` (what the container header must declare; `header_size + text_size + data_size + bss_size == segment_memsz`, `table_entries * 4 <= data_size`), `segment_memsz` (that segment's memsz), `size` (0 or `header_size + text_size + data_size`), `sha1`, `crc32` |
| `[[files]]` | `path`, `role` (`iop_module`, `iop_image`, `system_cnf`, `other`), `size`, `sha1`, `crc32` |
| `[not_extracted]` | `paths`: disc paths the intake never extracts; a trailing `/` marks a directory |
| `[iop]` (optional) | `reset_image`: the disc path of the IOP update image the game resets the IOP with (a `[[files]]` entry with role `iop_image`); `[[iop.modules]]` rows in load order, each `name` (upper-case basename of a `[[files]]` entry with role `iop_module`, without `.IRX`; unique) and `services` (the runtime's native services that answer for the module: catalogue names such as `padman.v1`, or `null:0x<sid>` for a server that acknowledges every call; empty when the module has no RPC server). From M4 (ADR-0014) `services = ["interpret"]`, alone in its row, loads the module's IRX into the IOP interpreter instead (session A; the sound rows are flipped in bring-up). See ADR-0011, ADR-0014 and `Docs/milestones/M3-boots.md` |
| `[title]` (optional) | What "the title screen" is for `dq8-game --until title`: `overlay` (an overlay name that must be resident), `variable` (a guest address in the main program, aligned to `width`), `width` (1, 2 or 4 bytes, little-endian unsigned) and `value` (what the variable holds on the title screen) |
| `[display]` (optional) | The game's own screen-size option (M5 session C): `widescreen_variable` (a guest address in the main program, aligned to `widescreen_width`), `widescreen_width` (1, 2 or 4 bytes, little-endian unsigned) and `widescreen_value` (what the variable holds when the game draws 16:9; it must fit the width). `dq8-game --aspect auto` presents at 16:9 while it holds that value and at 4:3 otherwise (`src/game/display_watcher.h`) |
| `[movie]` (optional) | `player_entries` (4-byte-aligned main-program addresses of the movie player's entry points, which `--movies skip` and `blank` override), optional `finished_query` (the player's "movie finished?" function, which they make report done), `scene_unit` (an overlay name), `scene_functions` (addresses inside the overlay window, the fallback override targets). Optional `[[movie.timelines]]` rows: a scene timeline that runs alongside a movie on its own frame counter (ADR-0013, proposed). Each row has `name` (our label: `a-z`, `0-9`, `-`; unique), `overlay` (an overlay name that must be resident), `stage_variable`, `stage_width` (1, 2 or 4 bytes, little-endian unsigned; the variable aligned to it) and `stage_value` (what the stage variable holds while the timeline runs; it must fit the width), `counter` (a 4-byte-aligned signed 32-bit word the scene steps up from 0) and `skip_to` (1 to 2³¹−1: the step the game itself jumps to when the player skips the movie). Both variables lie in the main program or in the overlay's data or bss, never its text. `--movies skip` writes `skip_to` to the counter at a vblank when the overlay is resident, the stage variable holds `stage_value` and `0 < counter < skip_to` (`src/game/movie_timelines.h`). Optional `[movie.sce_mpeg]` (M4, ADR-0015): `create`, `delete`, `add_callback`, `add_str_callback`, `demux_pss_ring`, `get_picture`, `get_picture_inner`, `is_end`, `reset`, `ipu_init`, `video_stream_callback`, all required, each a 4-byte-aligned main-program address: the sceMpeg SDK entry points the movie HLE replaces or hooks, and the game's video stream callback it replaces; optional `player_open` (where the HLE learns the movie's name so the `movie` events carry it: the game's player open, or a function the open calls through the dispatcher before sceMpegCreate when the open itself is reached by a tail jump; 0 or absent: no hook) and `player_open_name_arg` (0 to 3: which of `$a0`..`$a3` holds the name as a C string) |

Sizes of 0 and empty hashes mean "not recorded yet"; `dq8ctl extract --emit-profile` prints the rows with the observed values. The header integrity values are always required: for a new region, read them with `dq8ctl info <file.BIN>` on an overlay extracted by hand (CLAUDE.md shows the 7z command). Verification stops on an unknown boot hash (the region gate, architecture.md §14) and then cross-checks the ELF entry point, load address, main segment size and each overlay's segment (by `segment_index`) and the listed files' presence and sizes; it then parses every overlay's container header from the image and checks `id`, the three sizes and the table entry count against the row and `header_size + text + data + bss` against the segment. The extracted files' hashes are compared on extraction, and `baserom/<id>/manifest.toml` records each overlay's header fields under `[files.mwo3]`.

The file name is the disc serial (architecture.md §13.4), which is why `.gitignore` and the no-game-data check exempt `data/regions/*.toml` from the boot-file-name rules; the content rules still apply.

## Smoke-test inputs: `smoke/`

`smoke/smoke.toml` maps a region profile id to the input script (`Docs/formats/dq8-input-script.md`, our own presses) that takes a fresh build from boot to its title screen: `[profiles]` with `<profile id> = "<file>.dq8in"`. The setup's smoke stage runs `dq8-game --headless --movies skip --input-script <file> --until title --vblanks 3000`; a profile without a row runs to its `[title]` overlay (`--until overlay:NAME --vblanks 3000`), or for 600 vblanks without a `[title]` table. The script is also `local.boot_to_title_skip`'s input. The scripts are named for what they do, since serial-named files are refused outside `data/regions/`.
